对照：[`../specs/2026-09-15-ontocore-objects-relations-design.md`](../specs/2026-09-15-ontocore-objects-relations-design.md) §12。下文条目在 2026-09-15 规格中仍为缺口。

## 规格写了、实现仍缺

1. **审阅时改显示名 / 本地名**（规格 §6）  
   审阅页只有接受 / 拒绝 / 投影，不能改候选名称。终审标为 I6，修复时按「非必须」跳过。

2. **作业级有限次重试**（规格 §8）  
   抽取/LLM 失败会把作业标 `failed`，没有超时/429 的有限次重试。

3. **JSON-LD 导入**（规格要求 Turtle 与 JSON-LD 导入导出）  
   目前可导出 JSON-LD，导入只接 Turtle。

4. **错误信息全中文**（产品语言约束）  
   仓库层仍有英文异常句，API 用单词替换，会出现中英混杂。终审 I7，修复时跳过。

## 体验与测试缺口

- 审阅页 `?job=` 只填输入框，不自动加载候选。
- README 仍写「数据目录默认临时目录」；实现已改为 `ONTOCORE_DATA_DIR`，缺省 `./data`。
- 前端 `build` 不跑 `tsc`；页面几乎没有行为测试（主要是文案扫描）。
- 属性占用检查可能对不上实例 `data` 的键（LLM 常用显示名，计数用 IRI）。
- 候选 IRI 未强制落在工作本体前缀内。
- Neo4j 适配器每次操作新建 driver，无连接池。

## 明确不做（规格 §11，不是遗漏）

领域包、OCR、实例逐条审阅、关系多起点/多终点、完整公理编辑器、生产 SDK、抽取准确率门槛。
