## 1. 背景与目标

OntoCore 是本体管理工具：维护对象、属性、关系，从说明书抽取建议，投影实例到图。

产品语言（界面、对外 API 说明、错误信息）只用：

- **对象**：一种东西，有定义和属性
- **属性**：只挂在对象上的字面量字段
- **关系**：两个对象之间的连接（一条关系恰好一个起点对象、一个终点对象）
- **父对象**：简单父子；子对象继承父对象的属性与关系
- **实例**：文档或图里的具体东西，不是对象种类
- **编号**：界面上的稳定 id，不展示 IRI 一词
- **供应商**：模型调用的地址与密钥登记（不是抽取器）
- **数据源**：上传说明书并发起抽取的页面（侧栏与页标题；路由可仍为 `/upload`）

禁止出现：类、TBox、ABox、对象属性、数据属性、领域包。内部存储仍是受约束的 OWL 小剖面，那些词不出现在界面。

闭环：

1. 手工维护对象、属性、关系（含增删改）；新建对象时可同时加可选属性。本体页展示对象关系网。
2. 上传说明书 → 抽取 → 人审对象/属性/关系候选 → 写入权威本体。
3. 类型确认后一键投影建议实例到属性图；图页可删节点和边。
4. Turtle / JSON-LD 导出；Turtle 导入；改显示名后仍按 IRI 找到节点。

成功标准：空库启动（无领域包、无种子对象）；可增删改对象与关系；可上传中文说明书并审阅类型候选后投影；后续抽取对齐当前权威对象/关系。

明确不做：OCR、抽取准确率门槛、实例逐条审阅、关系多起点/多终点、多租户、工作流引擎、全量 OWL 2 DL、评测集 CI、领域包、Git Flow / 长期 `dev`/`test` 分支。

## 2. 权威分层与存储映射

- **类型层**：运行时用嵌入式 Oxigraph（内存）；权威落盘为 `ontology.nq`（每次写入原子替换）。不再把常驻 `oxigraph/` RocksDB 当作唯一真相，避免进程被杀导致库损坏。旧 `oxigraph/` 仅在没有快照时尝试迁移。
- **实例层**：属性图（Neo4j；测试可用内存图）。节点/边必须映射到已确认对象或关系。
- 图库不可用时，不得把实例写进类型层充数。

存储对应（只用于导入导出，不出现在界面）：对象 ↔ 命名类型；父对象 ↔ 单一 `rdfs:subClassOf`；属性 ↔ 字面量字段；关系 ↔ 两端对象之间的连接；实例不进类型层。

禁止：多继承、子对象覆盖同名属性、一条关系多个起点或终点。

序列化：Turtle / JSON-LD。自有 JSON 不是类型层权威。第一期一个工作本体，IRI 前缀默认 `https://ontocore.local/ns/working#`。IRI 写入后稳定；改名只改显示名与图侧 `onto_label`。

本机运行数据目录：`ONTOCORE_DATA_DIR`，缺省 `./data`（相对启动后端时的工作目录，开发时一般为 `backend/data`）。其中：`ontocore.db`（作业、候选、模型供应商密文）、`master.key`（或环境变量 `ONTOCORE_SECRET_KEY`）、`ontology.nq`（对象/属性/关系快照）。密钥只放本机，不进仓库；SQLite 与 JSON 都不存明文 `api_key`。旧 `settings.json` 在首次读取时迁入 SQLite 并去掉明文。

## 3. 架构

Python 后端 + TypeScript Web。四块：类型层服务、实例图层服务、抽取编排（文档 → 抽取器 → LiteLLM 结构化调用 → 候选）、Projector（IRI ↔ 图显示）。

插件边界：抽取器、LLM 供应商、RDF 实现、图库。没有领域包。抽取器入参：文档、当前权威类型层快照、LLM 网关、可选引导。

## 4. 数据模型（产品层）

与 2026-09-10 版相同：对象（显示名、定义、可选一个父对象）、属性（文本/数字/日期）、关系（单一起点与终点）、实例（不进人审队列，作业「投影到图」一次性写入）。删除对象/属性/关系在仍被引用时拒绝。

## 5. 组件与接口

### 5.1–5.6

DocumentIngress、Extractor（单一 LLM，见 2026-09-20）、CandidateStore、类型层仓库、GraphRepository / Projector 仍按上一版：抽取器只经 `complete_structured`；人审只有类型候选；投影跳过未确认类型。

### 5.3 LLM 与供应商

抽取器禁止直连某一家 SDK。调用经 LiteLLM。每条供应商记录：

| 字段 | 含义 |
| --- | --- |
| id | 稳定标识 |
| label | 显示名 |
| prefix | LiteLLM 调用前缀（如 `openai`、`deepseek`） |
| api_base | Base URL |
| api_key | 仅写入时提交；磁盘为密文；`GET` 不返回 |
| has_api_key | 是否已保存密钥（给界面占位，不是密钥本身） |
| model | 最近选定的具体模型名（短名，不含或可含 `/`） |

模型列表：`GET {api_base}/v1/models`（若 Base URL 已以 `/v1` 结尾则 `{api_base}/models`），Bearer 密钥。选项来自返回的 `id`。具体模型名与前缀拼成 LiteLLM 模型（已含 `/` 则不再加前缀）。可选 `thinking`。

作业必须带 `provider_id`（抽取供应商）与 `model`（抽取模型），以及 `embed_provider_id`（嵌入供应商）与 `embed_model`（嵌入模型）。抽取与嵌入可分属不同供应商；判重嵌入调用用 `embed_provider_id` 的凭据。可选引导对象/关系（不引导实例）。

### 5.7 HTTP API

- 对象 / 属性 / 关系 CRUD、对象关系网
- 数据源作业（`POST /api/jobs`）、类型候选接受/拒绝、投影到图
- 实例网查询、删除实例节点/边
- OWL 导出（Turtle、JSON-LD）；导入（Turtle，`force`）
- `GET/PUT /api/settings`：模型供应商列表。`GET`/`PUT` 响应含 `has_api_key`，不含 `api_key`。`PUT` 仅在字段非空时更新密钥。
- `GET /api/settings/prefixes`：LiteLLM 调用前缀目录，供设置弹窗下拉。
- `POST /api/settings/models`：拉取某一供应商的模型列表
- `POST /api/settings/test`：最小请求测该供应商联通

HTTP 失败体与作业错误见 [`2026-09-21-fault-logging-design.md`](2026-09-21-fault-logging-design.md)。

没有领域包 API。设置里没有抽取器字段。

## 6. 页面

五个页签。视觉参考 Dify 浅色工作台：白侧栏、灰画布、白卡片、大圆角、主色约 `#155eef`、Noto Sans SC。成功/错误用右上角弹出 tips，不嵌在表单正文里。

**本体**  
主页面对象关系网铺满；顶栏「新建对象」「新建关系」打开弹窗。新建对象弹窗可附带可选属性行。点图上节点打开对象详情弹窗（改显示名/定义/父对象、属性、删除）。点图上的边打开关系详情弹窗（可删除）。主页面不放对象列表。新建表单不嵌在主页面正文里。

**数据源**  
侧栏与页标题均为「数据源」，路由仍为 `/upload`。文件 + 抽取供应商 + 抽取模型（列表来自该供应商接口）+ 可选 thinking + 嵌入供应商 + 嵌入模型（列表来自嵌入供应商接口，可与抽取分开选）+「选择引导」。无领域包。

**审阅**  
仅类型候选：接受 / 拒绝。对象/关系若有相似，接受时对话框选目标并选覆盖、新增或融合。属性只新建。作业「投影到图」。不提供实例逐条接受。当前实现不提供审阅时改候选显示名（见 §12）。

**图**  
实例关系网，可按对象筛选，可删节点和边。

**设置**  
上下布局：上方**模型供应商**用卡片网格（面板内方形磁贴：名称、前缀、当前模型），点卡片打开编辑弹窗（名称、前缀、Base URL、密钥、测试用模型；按钮「拉取模型」「测试」「删除」「保存」）。打开弹窗后按该供应商自动拉取其支持的模型，填入「测试用模型」下拉；也可再点「拉取模型」刷新（例如改了 Base URL 或密钥）。进入设置页不预先拉全部供应商的模型。「新增模型供应商」打开空白创建弹窗（无「删除」）。不放空占位框。密钥框不回填明文，已保存时占位「已保存密钥」。保存时校验名称、调用前缀、Base URL；新增或尚未保存密钥时还须 API Key。空白（含仅空格）不提交，弹出 tips 列出缺项（如「请填写名称、Base URL、API Key」）。测试用模型不是保存必填。不在输入框下显示错误。通过后再 `PUT /api/settings`。下方 Turtle 导入与导出链接。

## 7. 数据流

1. 用户在设置登记供应商并保存（含当前选中模型）。
2. 数据源页选抽取供应商与抽取模型、嵌入供应商与嵌入模型、可选引导 → Job（抽取固定 LLM）。
3. 解析与抽取。失败则 `failed`。
4. 人审类型后「投影到图」。
5. 本体页走类型层，图页走实例。导出 Turtle / JSON-LD。

作业状态仍可包括 `partial`、`types_accepted_graph_pending`。已确认类型不因后续抽取失败自动回滚。

## 8. 错误处理

对外约定以 [`2026-09-21-fault-logging-design.md`](2026-09-21-fault-logging-design.md) 为准：HTTP JSON 含 `detail`（友好中文）、`code`、`kind`、`request_id`；界面 tips 不展示故障码与堆栈。设置拉取/测试：密钥无效、超时、断网 DNS、供应商 HTML/LiteLLM 原文分别映射为中文，不得把异常类名或错误页送进 tips。作业失败 `error` 仅为中文，另存 `error_kind`。作业级有限次重试**尚未实现**（失败即 `failed`）。类型写入冲突 400；删除仍被引用 409。投影时图不可用则停在可重试状态。

## 9. 测试与协作

新行为、修 bug、改接口必须有会失败再转绿的测试，否则不算完成、不能提交（纯文档/忽略规则除外）。后端 `backend/tests/`（临时数据目录，禁止打真实供应商）。前端 `vitest`（现有文案/接线测试）+ 改界面须打开页面走主路径。

Git：主干 `main`，精简 Conventional Commits，默认不开功能分支。规范见 `docs/dev-standards.md`、`docs/git-workflow.md`。

回归仍包括：空库、对象关系 CRUD、抽取器契约、审阅不暴露实例接受、投影跳过未确认类型、无 `force` 时同 IRI 导入拒绝、图上删除实例。另须覆盖：供应商 CRUD、模型列表解析、联通探测、旧单模型 `settings.json` 迁成默认供应商。
