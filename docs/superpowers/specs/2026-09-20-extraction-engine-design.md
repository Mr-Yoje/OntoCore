# OntoCore 设计：抽取引擎（引导约束 + 判重导入）

日期：2026-09-20  
状态：已落地  
范围：去掉标题硬对齐抽取器；单一 LLM 抽取；可选引导；新对象/关系判重；接受时覆盖 / 新增 / 融合  
产品语言：只用对象、属性、关系、定义、实例、父对象、编号、供应商、数据源。界面把稳定 id 称作**编号**，不展示 IRI 一词。内部仍用 IRI。侧栏与数据源页标题均为「数据源」，路由可仍为 `/upload`。  
取代：[`2026-09-15-ontocore-objects-relations-design.md`](2026-09-15-ontocore-objects-relations-design.md) 中关于 `hybrid` / `llm_only` / `rules_only`、数据源页抽取器选择、默认抽取 `hybrid`、接受类型候选仅「写入新建」的条款。其它章节（类型层 `ontology.nq`、供应商密文、页面视觉等）仍以 2026-09-15 为准。

## 1. 目标

一次作业从说明书抽出对象（含属性）、关系和实例。用户可勾选已有对象、关系作为**软约束**（可不选）：实例含义接近所选对象或关系时对齐到那些编号；对不上的可以提议新对象、新属性、新关系。约束不是白名单，不是「只许抽这些」。引导不选实例。

抽取提示里**只放勾选项**。未勾选的已有对象/关系不进抽取提示，以免冲淡引导。重复风险用抽完后的判重补：向量初筛（可选）+ **一次**精选 LLM，对照未勾选项。人审时新对象/关系仍先显示为建议新建；有相似则接受时选覆盖、新增或融合。

成功标准：数据源页不再出现三种抽取器；空引导与有引导两条路径都能产出可审候选；有相似标记时可三种导入；覆盖/融合写回已有编号，新增发新编号；测试用假 LLM / 假嵌入，不打真实供应商。

## 2. 架构（方案 1）

去掉 `RulesOnlyExtractor` 与 `HybridExtractor`。注册表只保留一条抽取路径（作业字段记为 `llm`）。历史作业若仍写着 `hybrid` / `rules_only` 只在列表里原样展示，不再执行旧实现。

一次作业内顺序：

1. 解析文档。
2. 抽取（短文一次 / 长文按标题多块，结果合并）。
3. 对新对象和新关系判重（属性、实例不判重）。
4. 写入候选库（对象/关系带 `similar_to`）。
5. 人审：接受对象/关系时按模式写入类型层；实例仍经「投影到图」。

融合发生在点接受时，不在作业抽取阶段。

## 3. 数据源与引导

表单：文件、抽取供应商、抽取模型、可选 thinking、嵌入供应商、嵌入模型、「选择引导」。抽取那栏标签为「抽取模型」（不用「具体模型」）。抽取与嵌入各用独立下拉：嵌入供应商可与抽取供应商不同；嵌入模型列表来自嵌入供应商接口。必须选抽取供应商与抽取模型、嵌入供应商与嵌入模型（不再有「不使用嵌入」）。

「选择引导」打开弹层：当前对象（按父对象成树）、关系列表。可搜索显示名，多选，可清空。按钮旁显示已选数量。默认为空。勾选对象后，该对象上的属性自动进入引导，不单独勾属性。引导不选实例。

弹层数据复用已有接口（对象/关系快照），不另做领域包。

作业记录保存：`provider_id`（抽取供应商）、`model`（抽取模型）、`thinking`、`embed_provider_id`（嵌入供应商）、`embed_model`（嵌入模型）、引导对象/关系编号列表。

`POST /api/jobs` 不再接受有意义的抽取器三选一；服务端一律走 `llm`。可忽略旧客户端传来的 `extractor` 字段。必填 `provider_id`、`model`、`embed_provider_id`、`embed_model`。缺抽取模型 400「请选择抽取模型」；缺嵌入模型 400「请选择嵌入模型」；缺嵌入供应商 400「请选择嵌入供应商」。所选抽取/嵌入供应商须已在设置中登记，否则 400。

## 4. 抽取

### 4.1 提示

系统说明：根据文档抽取对象（含属性）、关系和实例；`guides` 为软约束；实例含义接近引导中的对象或关系时对齐到其编号；确实无法对齐可提议新对象、新属性、新关系。

用户消息为 JSON：`guides`（所选对象含属性、关系；界面不引导实例）+ `filename` + 本段 `text`。未勾选类型不得出现在 `guides` 或其它提示字段中。

输出仍为五类数组：`object_candidates`、`attribute_candidates`、`relation_candidates`、`instance_suggestions`、`instance_rel_suggestions`。服务端按字段白名单组装；非法条目记失败块。

### 4.2 切块

以 `ParsedDocument.full_text` 的字符数 `len(...)` 为准：≤ 8000 则整篇一次调用。超过则按 `heading` 分节；标题前的正文并入第一节。每一节一次 `complete_structured`，共用同一 `guides`。服务端合并列表。单块失败记入 `block_failures`，其它块继续。全部块失败则作业 `failed`。

不再做标题显示名等于对象显示名的硬绑定。

## 5. 判重

对照集：未勾选的已有对象、未勾选的已有关系。对象只和对象比，关系只和关系比。无新对象且无新关系、或对照集为空：跳过判重。

嵌入与抽取可选用不同供应商；嵌入模型从嵌入供应商的列表另选。判重向量调用使用作业 `embed_provider_id` 对应供应商的地址与密钥（不以抽取供应商为准）；精选仍用抽取供应商与抽取模型。嵌入文本：显示名 + 定义。嵌入调用成功：每条新建议保留余弦相似度最高的至多 5 条，不做额外分数阈值。嵌入调用失败：不做初筛，精选的对照为全部未勾选项。历史作业若缺 `embed_provider_id`，嵌入回退到抽取供应商（仅兼容旧行）。

精选：与抽取同一供应商、同一抽取模型，**一次**结构化调用，覆盖本作业全部待判新对象和新关系。输入为各新项的显示名、定义、证据及其对照列表。输出为每条新建议「确认为相似」的已有编号列表（可空）。

写入候选：对象/关系仍为建议新建，附 `similar_to`（编号 + 显示名）。实例候选无此字段。精选失败：作业 `partial`，抽取候选保留，`similar_to` 为空，错误说明判重失败。

## 6. 人审导入

属性候选：仍单独接受/拒绝，无覆盖/融合。接受属性即新建属性（编号按抽取）。

实例：不走三种模式。类型确认后「投影到图」。无实例逐条接受。

对象/关系：

- `similar_to` 为空：接受 = **新增**（创建抽取结果，新编号）。界面不弹模式。
- 非空：必须选一个 `similar_to` 中的目标编号，再选模式：
  - **新增**：忽略目标，按抽取结果新建。
  - **覆盖**：写回目标编号。对象：定义、父对象、属性整份换成这次抽取；该对象上这次没提到的已有属性删除。抽取里属性若挂在新对象编号上，写入时改挂目标编号。关系：定义与两端对象整份换成这次抽取。
  - **融合**：把目标当前内容与这次抽取（对象含属性，关系含两端）交给抽取同一模型，一次调用得到合并结果。对象结果含显示名、定义、父对象编号、属性列表（显示名、定义、字面类型）；关系结果含显示名、定义、两端对象编号。结果必须包含新抽要点，不得只复述旧项。写回目标编号（编号不变）；对象属性以融合结果为准（整份替换）。

`POST /api/type-candidates/{id}/accept` 增加 JSON：`mode`（`create` | `overwrite` | `merge`）、`target_iri`（覆盖/融合必填）。无相似时 `mode` 缺省或只能是 `create`。

失败：目标编号已不存在 → 400，候选仍为建议。融合调用失败或结构不合法 → 400，不写库。拒绝候选不变。投影仍跳过未确认类型。

审阅列表：有相似则标明「与某某相似」。有相似时点接受打开对话框（目标 + 三种模式）。

## 7. 错误与状态

作业：解析失败 `failed`；抽取部分块失败或精选失败且仍有候选 → `partial`；成功无失败块 → `completed`。已确认类型不因后续作业失败回滚。

界面：成功/错误用右上角 tips。覆盖/融合/新增的校验错误用中文。

## 8. 测试

假 LLM、假嵌入，禁止真实供应商。后端 `backend/tests/`，前端 vitest + 改数据源/审阅页须打开页面走主路径。

至少覆盖：

- 抽取提示只有勾选引导，不含未勾选对象。
- 短文一次调用；长文（>8000 字且多标题）多块合并；单块非法草稿 → 失败块 + 其余保留。
- 新作业必带嵌入供应商与嵌入模型：每条新对象/关系对照不超过 5 条初筛；一次精选覆盖全部新对象和新关系。
- 嵌入失败：精选对照未勾选全量；抽取结果仍在。
- 精选失败 → `partial`，`similar_to` 空。
- 接受：无相似 → 新增；覆盖删除未提到的属性；融合一次 LLM 后写回目标；新增发新编号。
- 属性/实例路径无三种模式。
- 数据源页无 hybrid / llm_only / rules_only；有「选择引导」。有相似时审阅走三种模式对话框。

## 9. 非目标

领域包；OCR；实例级覆盖/融合；属性单独判重；未勾选类型进入抽取提示；作业拆成「抽取 / 对齐」两段可见状态；精选或融合打真实网；保留 `rules_only` 作离线路径。

## 10. 技术选型变更

| 部分 | 选择 |
| --- | --- |
| 抽取 | 单一 LLM 路径（作业 `extractor=llm`） |
| 切块 | `len(full_text) > 8000` 时按标题分节多次调用 |
| 嵌入 | 必选供应商与模型；LiteLLM embeddings；调用失败则跳过初筛 |
| 判重精选 | 与抽取同一模型，每作业一次 |
| 融合 | 接受时与抽取同一模型，每次融合一次 |
