# OntoCore 设计：对象与关系本体管理（第一期）

日期：2026-09-10  
状态：待用户审阅  
范围：模块化单体；非结构化文本抽取闭环；本体按对象 / 属性 / 关系管理  
对照：旧规格 [`2026-09-10-ontocore-design.md`](2026-09-10-ontocore-design.md) 保留不改。实现以**本文件**为准。

## 1. 背景与目标

OntoCore 是本体管理基础设施：管理本体，从文本抽取，同时服务知识工程师与后续业务系统。

产品语言（界面、对外 API 文案）只用：

- **对象**：一种东西，有定义和属性
- **属性**：只挂在对象上的字面量字段
- **关系**：两个对象之间的连接（一条关系恰好一个起点对象、一个终点对象）
- **父对象**：简单父子；子对象继承父对象的属性与关系
- **实例**：文档或图里的具体东西，不是对象种类

内部类型层仍是受约束的 OWL 小剖面；人不可见「类 / 对象属性 / 数据属性 / TBox / 领域包」等词。

第一期闭环：

1. 手工维护对象、属性、关系（含增删改），本体页展示**类型关系网**。
2. 上传保险产品说明书 → 可插拔抽取 → 人审**类型**候选 → 权威 OWL。
3. 类型确认后**一键投影**建议实例到属性图；图页展示**实例关系网**；错了在图上删除。
4. OWL 导入导出；改显示名后仍按 IRI 找到节点。

成功标准（必达）：

- 空库启动：无领域包、无种子对象。
- 用户可增删改对象（含定义、父对象、属性）和关系；类型关系网随编辑更新。
- 用户可上传 1～2 份中文说明书；系统产出建议新对象/属性/关系与建议实例。
- 人只审类型候选；接受后写入 OWL。已确认类型上的建议实例经一键投影进图并可浏览、可删。
- 后续抽取对齐当前权威对象/关系，而不是任何预置领域包。
- OWL 可导出（Turtle / JSON-LD）并再导入。
- 可演示一次显示名/映射更新：查询用新名，IRI 稳定。

明确不做：OCR、抽取准确率门槛、实例逐条审阅、关系多起点/多终点、多租户、工作流引擎、全量 OWL 2 DL、评测集 CI、领域包。

## 2. 权威分层与 OWL 映射

- **类型层（唯一模式真相）**：RDF + 受约束的 OWL 剖面，存嵌入式 RDF 库。
- **实例层（实例真相）**：属性图（Neo4j；测试可用内存图）。节点/边必须映射到已确认对象或关系。
- 图库不可用时，不得把实例写进 OWL 充数。

产品概念与 OWL 小剖面的对应（只用于存储与导入导出，不出现在界面）：

| 产品 | OWL |
| --- | --- |
| 对象 | 命名类 |
| 父对象 | `rdfs:subClassOf`（单一父对象） |
| 属性 | 数据属性；`rdfs:domain` 为该对象；`rdfs:range` 为字面量类型 |
| 关系 | 对象属性；`rdfs:domain` 为唯一起点对象；`rdfs:range` 为唯一终点对象 |
| 可选互斥 | 两个命名类上的 `owl:disjointWith` |
| 实例 | 不进类型层权威；只进图 |

禁止第一期写入：复杂匿名类、一般角色包含、完整 OWL 2 DL、多继承、子对象覆盖父对象同名属性。

序列化从第一天使用 Turtle / JSON-LD。自有 JSON 不是类型层权威格式。

第一期只维护 **一个** 工作本体。内部 IRI 前缀默认 `https://ontocore.local/ns/working#`。创建对象/属性/关系时可指定本地名；一旦写入权威库，IRI 为稳定主键。改名只改 `rdfs:label` 与图侧 `onto_label`。第一期不提供改 IRI。不把图原生 label 当主键。

## 3. 架构

Python 后端 + TypeScript Web 的模块化单体。核心经端口交互，适配器可替换。

四块核心：

1. **类型层服务**：手工提交与「已接受的类型候选」写入权威 OWL；导出/导入。
2. **实例图层服务**：仅投影已确认对象/关系上的实例与边。
3. **抽取编排**：文档解析 → 抽取器插件 → LiteLLM 结构化调用 → 候选（类型 + 建议实例）。
4. **同步器（Projector）**：维护 `IRI ↔ 图类型/显示属性`；变更更新映射与显示名，不把 Neo4j 原生 label 当作可随意改的主键。

插件边界：抽取器、LLM 厂商、RDF 实现、图库。

**没有领域包。** 不提供种子 OWL、目标类型清单、领域包设置、作业上的领域包参数。抽取器入参只有文档、当前权威类型层快照、LLM 网关。仓库启动时类型层为空。

## 4. 数据模型（产品层）

### 4.1 对象

必有：显示名、定义、稳定 IRI。可选：恰好一个父对象。

增删改均支持。删除前必须同时满足：

- 没有实例占用该对象；
- 没有其他对象以它为父对象；
- 没有关系以它为起点或终点。

否则拒绝删除并返回原因。

子对象只读继承父对象（及祖先）的属性与关系。第一期不支持多继承，不允许子对象覆盖同名属性。

### 4.2 属性

只属于某个对象的字面量字段。字段有显示名、说明、字面量类型（文本、数字、日期；第一期这三种）。

不指向其他对象。指向其他对象的一律建关系。

在所属对象上增删改。已有实例填了该属性时，删除属性须拒绝或要求先清实例值（第一期：拒绝删除并说明）。

### 4.3 关系

连接类型：显示名、定义、恰好一个起点对象、恰好一个终点对象。方向明确：A「包含」B 不等于 B「包含」A。

多种对象要共用同一关系时，必须先建共同父对象，关系挂在父对象上。第一期不支持一条关系勾选多个起点或终点，也不支持「允许的对象对列表」。

已有实例边占用时不能删除该关系。

类型关系网：节点 = 对象，边 = 关系（从起点到终点）。

### 4.4 实例

具体对象实例与具体关系边。不进类型层。所用对象/关系必须已在权威类型层中，才能投影到图。

建议实例由抽取产生，**不进入人审队列**。人审只处理对象/属性/关系候选。类型确认后，用户对当次作业执行「投影到图」：已对齐且类型已确认的建议实例与边一次性写入图；未确认类型的跳过并列出原因。错误实例在图页删除。

## 5. 组件与接口

### 5.1 DocumentIngress

输入：PDF、DOCX、纯文本。  
输出：规范化纯文本 + 结构块（标题、段落、列表），块带稳定 `block_id`。  
加密 PDF、空文本、扫描件无文字：作业失败。第一期不做 OCR。

### 5.2 Extractor

`extract(doc, tbox_snapshot, llm) → ExtractionResult`

- `tbox_snapshot` 是当前权威对象/属性/关系/父子的只读快照（含显示名与定义），不是领域包。
- `ExtractionResult` 只含候选：建议新对象、属性、关系；建议实例与实例边。抽取器不得写权威 OWL 或图。
- 能对齐到快照中已有对象/关系则对齐；否则进入建议新类型。未确认类型不得作为图类型。
- 内置：`hybrid`（默认：规则/版式切块 + LLM 绑定类型与关系）、`llm_only`；预留 `rules_only`。
- 作业或全局配置选择抽取器。切块不得依赖预置领域章节清单；可用通用标题启发式 + 当前对象显示名匹配。

### 5.3 LLM Gateway（LiteLLM）

抽取器只调用 `complete_structured(schema, messages)`。  
经 LiteLLM 路由 OpenAI 兼容、国内云、本地端点。禁止在抽取器内直接引用某一厂商 SDK。

### 5.4 CandidateStore

- 类型候选：对象、属性、关系；每条带证据（原文片段、`block_id`、置信度）。状态：`proposed` / `accepted` / `rejected`。
- 建议实例与实例边：同样入库并带证据，状态为 `proposed` / `projected` / `skipped`（类型未确认被跳过）。**没有** `accepted` 人审态。投影成功改为 `projected`。
- 不合 schema 的模型输出不得入库。

### 5.5 TBoxRepository（类型层仓库）

写入来源仅三路：手工 API、类型候选 `accepted`、OWL 导入。  
导入默认：同 IRI 已存在则拒绝覆盖，除非请求显式 `force=true`。  
同一本体同一时刻仅一个确认/导入写事务；抽取只读快照。

手工与候选写入必须满足：父对象存在；关系起点/终点为已有对象；属性只挂一个对象且 range 为字面量。

### 5.6 GraphRepository 与 Projector

图写入仅来自：「投影到图」时所用对象/关系均已在权威类型层中的建议实例。  
Projector 登记 IRI ↔ 图侧类型名，节点/边上写 `onto_iri`、`onto_label`。  
同步演示：修改已确认对象的显示名或映射名 → 更新映射表与 `onto_label`；查询 API 返回新显示名；节点仍按 `onto_iri` 查找。

图页支持删除实例节点与边（纠正一键投影中的错误）。删除实例不回写 OWL。

### 5.7 HTTP API 与前端

同一后端。API 分组：

- 对象 / 属性 / 关系 CRUD、类型关系网查询
- 上传与作业状态、类型候选审阅、投影到图
- 实例关系网查询、删除实例/边
- OWL 导入导出、抽取器与模型设置

没有领域包 API。

## 6. 页面

五个页签。文案只用对象、属性、关系、定义、实例。

**本体**  
对象列表：新建、改显示名/定义/父对象、删除。选中对象后维护其属性。关系列表：名称、定义、起点、终点。  
主区为类型关系网：节点是对象，边是关系；点节点看定义与属性，点边看关系。空库时网为空，提示先建对象。

**上传**  
上传 PDF / DOCX / 纯文本，选择抽取器和模型，查看作业进度。无领域包选项。

**审阅**  
仅类型候选：建议新对象、属性、关系。接受 / 拒绝 / 改显示名或本地名。  
类型审完后，该作业出现「投影到图」：将已对齐且类型已确认的建议实例一次性写入图。不提供实例逐条接受/拒绝。

**图**  
实例关系网：节点是具体实例，边是实际关系。可按对象筛选。点节点看属性值与证据。可删节点和边。图库不可用时说明原因。

**设置**  
抽取器、LiteLLM 模型、OWL 导入导出。无领域包。

## 7. 数据流

1. 用户选择抽取器与模型，上传说明书 → Job `queued`。
2. 解析成功则抽取；失败则 `failed`。
3. 抽取器读取当前权威类型层快照：能对齐则对齐，否则 `proposed` 对象/属性/关系；同时写入建议实例（`proposed`），不写 Neo4j、不写权威 OWL。
4. 人审类型：接受则事务内写 OWL 并登记映射；拒绝则该类型不得用于投影。
5. 用户点「投影到图」：跳过未确认类型并列出原因；已确认的实例与边写入图，候选标为 `projected`；证据挂到图元。
6. 浏览：本体页走类型层；图页走实例查询。导出 Turtle / JSON-LD。
7. 改显示名/映射名后查询展示更新，IRI 稳定。

作业状态还包括：`partial`（部分块失败仍可审已成功类型候选）、`types_accepted_graph_pending`（图不可用，投影可单独重试）。已确认 OWL 不因后续抽取失败而自动回滚。

## 8. 错误处理

- 模型超时、429、厂商错误：作业级有限次重试；仍失败则 `failed`，已有候选保留，允许换模型重跑同一文档。
- 结构化输出校验失败：该块失败，作业可为 `partial`。
- 类型写入：IRI 冲突、父对象不存在、关系起点/终点未知、属性指向另一对象 → HTTP 400，事务不提交。
- 删除对象/属性/关系时仍被引用 → HTTP 409，说明引用方。
- 投影：未确认类型跳过；Neo4j 宕机则停在 `types_accepted_graph_pending`。
- 不引入跨 RDF 与 Neo4j 的分布式事务；顺序为先权威类型层，后图投影，图失败可重试。

## 9. 测试

必做：

- 空库启动：无领域包模块、无种子对象、类型关系网为空。
- 对象/属性/关系 CRUD；父子继承可见；关系拒绝多个起点或终点；删除在仍被引用时失败。
- 抽取器契约：假 LLM 固定输出时，`hybrid` 与 `llm_only` 产出合法 `ExtractionResult`，且入参不含领域包。
- 审阅：接受对象后 OWL 含对应类；拒绝后投影不含该类型实例。候选审阅 API/UI 不暴露实例接受/拒绝。
- 投影：一键写入已确认类型实例；未确认的跳过并给原因。
- 导入：无 `force` 时同 IRI 拒绝。
- 同步：改映射后 API 显示新名，按 IRI 仍能找到节点。
- 图上删除实例后查询不再返回该节点。
- 一份脱敏说明书片段 fixture，作回归演示，不设准确率门槛。

## 10. 技术选型（第一期默认）

| 部分 | 选择 |
| --- | --- |
| 后端 | Python |
| 前端 | TypeScript |
| LLM | LiteLLM 多厂商 |
| 类型层存储 | 嵌入式 RDF，默认 Oxigraph，经 Repository 接口隔离 |
| 实例存储 | Neo4j |
| 作业/候选元数据 | SQLite |
| 默认抽取 | hybrid |

以后可拆抽取集群或独立 OWL 服务，不作为第一期交付。

## 11. 非目标与后续

本期不做：领域包、OCR、实例逐条或分组人审、关系多起点/多终点、完整公理编辑器、生产级多语言 SDK、除文本外的数据源、抽取准确率门槛。

后续（不在本期计划中展开实现）：多数据源适配器、评测集与指标、OCR、实例批量纠错、更多 OWL 公理、推理引擎、流水线平台、类型层与图双写分布式事务。
