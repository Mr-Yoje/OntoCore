# OntoCore 设计：作业内去重、阶段状态与分阶段进度

日期：2026-09-23  
状态：已确认（已实现）  
范围：多切片抽取后的对象/关系作业内合并；作业状态机重梳；抽取 / 合并 / 判重各自进度；与对库判重、人审的衔接  
相关：[`2026-09-20-extraction-engine-design.md`](2026-09-20-extraction-engine-design.md)、[`2026-09-22-async-jobs-progress-design.md`](2026-09-22-async-jobs-progress-design.md)  
参考：LightRAG（切块抽取 → 跨块按名聚合 → 描述合并 → upsert）；本设计只借鉴「跨块归并 + 合并描述」节奏，库内写入仍走 OntoCore 人审三种导入。

## 1. 目标

长文多切片时，同一对象/关系常被抽出多条。需在**进入人审前**做作业内去重，再对库挂 `similar_to`。同时把作业状态拆成可理解的阶段，并为抽取、合并、判重提供**独立进度口径**。

成功标准：

- 多切片同名或高相似对象/关系在审阅列表中合并为更少条数。  
- 列表状态能区分抽取中 / 合并中 / 判重中 / 待审阅。  
- 各阶段进度百分比按该阶段分母计算，不混用。  
- 对库判重与人审三种导入行为保持；测试不打真实供应商。

## 2. 流水线（方案 1）

`JobService.run`（或等价编排）顺序：

1. 解析文档。  
2. **`extracting`**：按现行切块规则多次 LLM 抽取，合并列表（可含重复）。  
3. **`merging`**：作业内对象/关系成簇并模型合并。  
4. **`aligning`**：对库向量初筛（可选）+ **一次**精选 LLM，写 `similar_to`。  
5. 写入候选库 → 终态 `reviewable` / `reviewable_partial` / `failed`。

人审接受时的覆盖/融合仍在接受当下发生，不在本流水线自动写库。

## 3. 作业状态

| 内部 status | 界面 | 含义 |
| --- | --- | --- |
| `queued` | 待启动 | 已保存未调度 |
| `extracting` | 抽取中 | 按切片抽取 |
| `merging` | 合并中 | 作业内成簇 + 每簇模型合并 |
| `aligning` | 判重中 | 嵌入初筛 + 一次精选 |
| `reviewable` | 待审阅 | 可进人审（主成功路径） |
| `reviewable_partial` | 待审阅 | 有候选，但切块/合并/判重存在部分失败 |
| `failed` | 失败 | 无可用候选或关键失败 |
| `types_accepted_graph_pending` | 待投影 | 类型已接受，图投影未完成 |

**操作：**

- 可启动 / 重新抽取：`queued`、`failed`、`reviewable`、`reviewable_partial`、`types_accepted_graph_pending`（非 `queued` 时先清空错误与进度再从抽取跑全链路）。  
- 可审阅（列表「审阅」）：仅 `reviewable`、`reviewable_partial`。  
- 进行中（`extracting` / `merging` / `aligning`）：列表操作「—」。  
- 可编辑（PATCH）：仅 `queued`。  
- 进程重启：将仍为 `extracting` / `merging` / `aligning` 的作业标为 `failed`，错误文案同现 `OC-3108`（服务已重启，请重新抽取）。`queued` 保留。

**兼容读库：**

- `running` → 按 `extracting` 展示与进度语义。  
- `completed` → `reviewable`。  
- `partial` → `reviewable_partial`。  
- 写路径新作业只写新状态码；迁移可惰性映射或一次性 UPDATE。

## 4. 分阶段进度

字段仍用 `progress_done` / `progress_total`；**语义随当前 status 变化**。进入新阶段时按该阶段口径重置。界面只显示 `floor(done/total*100)%`（`total==0` 时：待启动「—」；阶段刚开始尚未定分母可「准备中」）。

### 4.1 `extracting`

- `total` = 切片数（规则同现行：≤8000 一字一切；>8000 按 heading）。  
- 每完成一块（成功或记入 `block_failures`）`done += 1`。  

### 4.2 `merging`

- 成簇完成后：`total` = **需要模型合并的簇数**（簇内条数 ≥ 2）。  
- 每完成一簇模型合并 `done += 1`。  
- 若无需模型合并的簇（全部单条）：`done = total = 0` 时视为该阶段完成并进入 `aligning`；或 `total=1, done=1` 显示 100% 后进入——实现任选一种，行为须为「不卡住、尽快进入判重」。推荐：**无待合并簇则直接进入 `aligning`，不强迫停留在 merging**。  

### 4.3 `aligning`

- 分母固定为 **2**（步骤：嵌入、精选）。  
- 嵌入结束（成功或失败跳过初筛）→ `done = 1`（50%）。  
- 本作业**一次**精选 LLM 成功 → `done = 2`（100%）。  
- 若跳过嵌入（未启用或无可嵌入项）：精选成功可直接 `done = 2`。  
- 精选失败：按现规则作业可 `reviewable_partial`，`similar_to` 空。

## 5. 作业内合并（merging）

### 5.1 成簇

- **对象**：规范化显示名相同 → 同簇；否则两两（或相对种子）嵌入相似度 ≥ **0.85** → 同簇。阈值本轮固定，设置不暴露。  
- **规范化**：去首尾空白；连续空白压成单空格；大小写折叠（ASCII）；其它 Unicode 保持原样除非另有明确规则。  
- **关系**：先将两端对象编号映射到合并后的代表对象；再按「关系规范化显示名 + 两端代表编号」成簇；名称不同时同样可用嵌入 ≥ 0.85（嵌入文本：显示名 + 定义，与对库判重一致）。  
- 属性、实例、实例关系：本轮**不**做跨切片合并簇；对象合并后，归属旧对象编号的属性候选改挂代表对象编号（实现时重写 `owner_iri`）。实例 `type_iri` / 实例关系端点若指向被合并对象编号，同步改写到代表编号。

### 5.2 模型合并

- 仅对条数 ≥ 2 的簇调用抽取**同一供应商、同一抽取模型**。  
- **一簇一次**结构化调用：输入簇内各条的显示名、定义、证据（对象含属性列表）；输出一条合并后的对象或关系（对象含属性列表）。须保留各条要点，不得只复述其中一条。  
- 合并失败：该簇保留置信度最高的一条（或首条）并记入失败信息，其它条丢弃或并入证据——实现选一种并在测试中固定；作业可降为 `reviewable_partial`。  

### 5.3 代表编号

- 簇内保留一条代表 `iri`（建议：置信度最高；相同则稳定排序取先）。合并输出写回该代表编号，供后续属性/实例改挂与对库判重使用。

## 6. 对库判重（aligning）

保持 [`2026-09-20-extraction-engine-design.md`](2026-09-20-extraction-engine-design.md) §5：

- 对照未勾选已有对象/关系；对象对对象、关系对关系。  
- 嵌入 Top5（失败则全量对照）+ **一次**精选覆盖全部新对象与新关系。  
- 结果挂 `similar_to`；人审新增 / 覆盖 / 融合不变。  
- **不**在 aligning 阶段自动写回本体。

## 7. 接口与前端

- `POST /api/jobs/{id}/start`：允许从可重抽状态重置后调度；进行中状态不可再次 start（`OC-1107`）。  
- 进度与状态字段随轮询返回；前端文案用 §3 表。  
- **过渡期（状态码未迁完前）**：库内仍可能写 `running` / `completed` / `partial`；界面须按 §3 兼容映射显示「抽取中」「待审阅」，列表「审阅」/「重新抽取」对 `completed`/`partial` 生效。迁码完成后以新码为准。  
- 详情「重新抽取」：重置后重跑 §2 全链路。  

## 8. 测试与验收

- 两切片抽出同名对象 → merging 后审阅仅一条（或代表一条）。  
- 显示名不同但嵌入 ≥ 0.85（假嵌入可控）→ 合并。  
- 每需合并簇调用一次合并 LLM（假 LLM 计数）。  
- 状态顺序经过 `extracting` → `merging` → `aligning` → `reviewable`（无合并簇时可跳过停留）。  
- `extracting` / `merging` / `aligning` 进度分母分别符合 §4。  
- aligning：嵌入后约 50%，精选成功 100%。  
- 旧状态读映射：`completed`→待审阅，`running`→抽取中。  
- 不打真实供应商。

## 9. 不做（本轮）

- 合并阈值可配、gleaning 多轮补抽。  
- 库内自动融合 / 跳过人审三种模式。  
- 属性单独审阅改造（另议）；实例级跨切片去重。  
- Celery；WebSocket。  
- 将合并与判重合成单一「处理中」状态。
